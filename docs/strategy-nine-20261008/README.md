## Алгоритм ставки

1. Исключить только reach≤0. Для каждой подгруппы усреднить исходную
   частоту bet по комбинациям на флопе, затем поровну по присутствующим флопам.
2. Топ-, вторая и третья пары разделены по БДФД; сохранить К1/К2.
3. Использовать согласованные целые проценты из промежуточной MD-таблицы.
4. ≤30% → X, ≥70% → B, строго между → X/B 50/50.
5. Глобальные правила — качественные тенденции внутри миксов. Дополнительные
   численные поправки по кикерам/рангам не моделировались; эталон исполнения
   смешанной клетки в итоговом аудите — одинаковые 50/50 для всех её рук.

К1: две оверкарты+БДФД на ЧС Bxx, средняя 9 / 8−.
К2: третья пара A-high, разрыв нижних рангов ≥3 дырки / 1–2 / подряд,
каждая подгруппа с БДФД / без. Пара не переносится в дро.

## Алгоритм защиты

1. Единицы EV исходных экспортов /10 = bb; EV fold=0 проверено.
2. **Только при оценке частот:** если для конкретной комбинации
   `max(EV_C,EV_R)−EV_F≤0.02 bb`, заменить её F/C/R на 1/0/0.
3. Применить явно принятые наблюдаемые классификаторы и фиксированные фолды.
   Для остальных усреднить частоты combo→board, нормировать
   `r=mean_R/(mean_C+mean_R)`.
4. На **всех** руках оставшейся наблюдаемой подгруппы, включая исходные
   чистые фолды и отрицательные EV, считать reach-взвешенные средние EC, ER.
   Оценка общего продолжения: `E=(1−r)*EC+r*ER`. Нельзя подменять это средним
   max(EC,ER) по каждой руке или выбрасывать отрицательные слагаемые.
5. E>0 → кандидат продолжения. Если E≤0 и оба средних чистых действия≤0,
   группа F. Если смесь отрицательна, но одно чистое положительно — явный
   конфликт для ручного решения, не автоматический EV-optimal выбор.
6. Пользователь дополнительно принял F для четырёх положительных пограничных
   клеток: BTN ЧС BBx low pocket (+.0056), BTN ЧС 9− low pocket (+.0170),
   UTG dry weak pair (+.0150), UTG ЧС 9− low pocket (+.0156 bb).
   Конфликт UTG связанные J+ гатшот без БДФД тоже F: C+.0013, R−.0973,
   смесь−.0276 bb. Порог .02 не превращён в скрытый универсальный порог
   среднего EV группы: это перечисленные одобренные решения.
7. Для принятого продолжения округлить отображаемое целое R%: ≤30 → C,
   ≥70 → R, иначе C/R 50/50. F уже определён и не рандомизируется.

Классификаторы защиты и исключение JT/AQT точно перечислены в утверждённом
MD. Непарные гатшоты делятся по БДФД. Low pocket на связанных T− защищается
только с OESD. QJT вернулся в общую подгруппу, `!QJT` отменено; это принятый
отрицательный хвост, а не новое условие действия. Все пары остаются парами.

## Формулы аудита

Для каждого исходного узла отдельно, w — native reach, p — стратегия солвера,
q — фиксированная человеческая политика, e — pure-action EV в bb:

```text
candidate_EV_i = sum_a q_ia * e_ia
signed_loss_i = mixed_EV_i − candidate_EV_i
clipped_loss_i = max(0, signed_loss_i)
node_frequency_a = sum_i w_i * q_ia / sum_i w_i
mean_loss = sum_i w_i * loss_i / sum_i w_i
joint(row,a) = sum_{i in row} w_i * policy_ia / sum_i w_i
composition_TV_pp = 50 * sum_{row,a} abs(joint_candidate − joint_solver)
```

P95/P99 — взвешенные по reach квантили clipped loss; хвосты — доля reach
с потерями >.10/.25/.50 bb. Это **локальная** проверка против фиксированного
солверного оппонента/продолжений, не exploitability, не root EV, не новый
solve и не совместная игра упрощённых PFR/BB друг против друга. Все веса
веток остаются исходными. Достоверность будущей суммарной потери всей игры
из этих отдельных чисел не следует. EV — аудит, не критерий выбора 30/70.
