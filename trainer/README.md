# Flop Lab — автономный тренажёр

Один готовый `poker_trainer.html`, открываемый двойным щелчком в современном
браузере. Сервер, сеть, CDN и установка зависимостей для игры не нужны.
Данные распаковываются штатным `DecompressionStream`, по одному флопу.

## Что является источником стратегии

- `approved-snapshot.json` — принятые действия и тексты разобранных ситуаций,
  первоначально импортированные из мануала. С 19.10.2026 мануал ведётся в
  `strategy_unified_flops.html`; внешний MD больше не обновляется. Это потребитель
  уже принятых правил, **не генератор человеческой стратегии**.
- Основные c-bet / BB-defense — текущие большие 12×9 таблицы MD.
  Отдельная ручная замена Two pair+ на R/C в прежней HTML-шпаргалке не
  распространяется на MD и не включена сюда.
- Донк, ответы на донк/чек-рейз, UTG после стаба — последние простые таблицы.
- UTG c-bet vs BTN сохраняет явно записанный в текущем разделе приоритет
  дро. Остальные ветки используют made-first.
- BTN против UTG не является учебной позицией; его два узла нужны для ответов
  оппонента. Всего 12 учебных веток и 14 экспортированных узлов.
- BB после рейза донка удалён из фильтров, индекса и переходов. После рейза
  донка упражнение заканчивается; ответ BB не подменяется другой стратегией.
- Источник — текущая структура MD: четыре большие таблицы и раздел
  «Остальные текущие ветки». Дополнительных упрощений основных действий нет.

## Раздача и диапазоны

Равномерная практика — единственный режим. Ветки выбираются чекбоксами в
постоянно открытой верхней панели, сгруппированными по трём ситуациям.
Выбранный префикс раздачи проигрывается до учебного решения. Оппонент получает
совместимые закрытые карты и действует по сохранённым частотам своего узла.
После нашего действия состояние переходит только в существующий узел;
терминальные фолды/коллы/чеки заканчивают упражнение. Отсутствующие ответы на
рейз в UTG vs BTN и тёрн/ривер не выдумываются. Нет денежных транзакций,
искусственного выигранного банка после колла или оценки адаптивной GTO-потери.

Диапазон стороны = её исходный префлоп-вес × вероятности **её собственных**
действий по линии. Для героя используются принятые таблицы, для оппонента —
исходные частоты. Native reach_probability не подставляется вместо этого:
он не равен независимому весу собственной руки. Флоп-карты исключаются.
При раздаче дополнительно учитывается несовместимость двух закрытых рук.
На вкладке диапазонов закрытые карты не используются как раскрытые блокеры.

Сравнение посередине показывает доли категорий, не equity и не EV. Вкладка
«Разборы флопа» показывает все сохранённые разборы этой категории флопа:
сначала исходные вводные абзацы, затем полные разделы. Выбор не зависит от
нашей руки. C-bet и защита BB явно подписаны; заголовки сохраняют позиции
и направление сравнения из MD. Цифры остаются агрегированными, не новым
расчётом конкретной раздачи. Поиск объяснения не меняет стратегию игры.

## Равномерность

Учебная ячейка = ветка × одна из девяти категорий флопа × категория руки.
Индекс строится только по совместимым рукам с положительным достижением и
определённым правилом. Пустые/недостижимые клетки не участвуют. Для исходных
правил число ячеек фиксируется в `test-report.json` после каждой сборки.

При каждом новом упражнении выбирается ячейка с минимальным числом целевых
показов (случайный выбор только среди равных), затем флоп и совместимые руки.
Префикс раздачи проигрывается до целевого решения; дальнейшие решения игрок
принимает сам. Целевые показы и естественные продолжения считаются отдельно:
гарантия равномерности относится к первым, не к естественным продолжениям.
В неизменном фильтре после полного круга каждая клетка показана
один раз. Смена фильтра сначала выравнивает его накопленные счётчики.

История очереди сохраняется только для планирования. Видимых счётчиков,
оценок сессии и панели прогресса нет. Все три вкладки подсказок доступны до
ответа. Основные таблицы показывают стандартное действие и цветные поправки
только текущей позиции; второстепенные — полную таблицу текущей ситуации.
Оформление повторяет HTML-шпаргалки, действия остаются из утверждённого MD.

BTN против донка доступен во всех категориях как одобренное учебное
отклонение соперника, хотя наша базовая таблица BB против BTN — полный чек.
Не применяется ко всем остальным недостижимым путям.

Любое действие с положительной вероятностью в принятом правиле получает
только `OK`. Неверный клик ничего не меняет: можно выбрать действие снова.
Рандомайзер — ориентир для игрока, а не дополнительное условие проверки микса.

## Сборка и тест

Из корня репозитория (Python 3, Node.js; стандартные библиотеки):

```powershell
python -B trainer/build.py --repo . --output output/trainer/poker_trainer.html
node trainer/prepare.cjs output/trainer
node trainer/test-ui.cjs output/trainer
```

Первый шаг пакует существующие CSV из STU002/STU004/STU005 и сохранённый
утверждённый снимок, без чтения MD. Правки разборов в HTML-мануале синхронизируем
с `approved-snapshot.json`. Второй проверяет правила, достижение и индекс,
проверяет отсутствие внешних runtime-зависимостей и собирает окончательный
HTML. Для обновления правил нужно отдельно согласовать и обновить снимок;
архивный MD импортируется только явно через `--manual`; `--refresh-snapshot`
нельзя применять для обычной пересборки, чтобы не вернуть устаревший текст.
`manualSHA` хранит происхождение исходного импорта, не хеш текущего HTML.
Production workbook pipeline не
затрагивается. Источники CSV фиксируются SHA-256 в `trainer-manifest.json`.

`trainer-test-data.json` и готовый HTML — локальные результаты в ignored output,
не коммитятся. В Git — исходники, компактный утверждённый снимок и тест-отчёт.

История равномерной очереди хранится в localStorage, если браузер разрешает
это для локального файла; иначе действует до закрытия вкладки. Счётчиков и
экспорта/импорта в интерфейсе нет. Автоматической синхронизации нет.

`test-ui.cjs` сверяет восстановленные из базы и поправок действия со всеми
непустыми ячейками основных таблиц, отбор позиции для второстепенных таблиц,
12 фильтров веток, множественный и пустой выбор, отсутствие старых настроек,
все разборы для каждой категории независимо от руки и обработку верных/
неверных кликов. `prepare.cjs` также проверяет отсутствие удалённой ветки.

Для временной QA (не требуется игроку):

```powershell
python -m http.server 8797 --bind 127.0.0.1 --directory output/trainer
```

Не открывать репозиторий целиком через сервер и не выставлять его в интернет.
